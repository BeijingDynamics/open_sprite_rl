# OpenSprite 工程笔记：从参考动作到真机稳定行走

[English version](SPRITE0825_STABLE_WALK_HANDOFF.en.md)

记录日期：2026-11-09。范围：恢复开始训练后退之前的成功基线，解释它为什么能工作，以及哪些路不值得重走。本文是工程交接，不是聊天摘要，也不是新的真机操作授权。

## 先读这一页

**成功基线是 Sprite0825 v5 四肩 J4340P + G74 `model3000` + 800 Hz ICM45686 原始六轴 + native 50 Hz actor + native 500 Hz 踝力控。训练是 Isaac Lab 中的速度指令 PPO + 无条件 AMP 风格先验。** 早期 BeyondMimic 风格 WBT 是参考跟踪和跨仿真验证阶段；不是最终上机的 actor。SuperMimic 是后来另做的实验，没有替换这一套真机基线。

- **已验证：** 2026-10-16，同一模型和增益连续三次完成电池供电、有防跌保护的 40 秒站立 → 前进 → 停步。前进指令是 `0.10 m/s`，不是外部仪器测出的实际地速。三次 CAN 控制均无截止时间超限，退出后验证 31/31 电机失能。操作者看到左腿蹬直明显改善、走得更直、启停稳定；这是视觉结论，不是左右脚清障高度或绝对航向的定量测量。
- **手柄范围：** 2026-10-19，同一基线增加 Xbox 前进、停步和左右转向；现场确认可用。120 秒入口仅开放前进 `0..0.10 m/s` 和转向 `±0.10 rad/s`，没有发布有动力后退。蓝牙断连的离线测试不等于运动中无线急停的完整实测。
- **别把“v5”当唯一标识：** 封存的 G74 训练 URDF 的 `waist_yaw_link` 质量是 `2.07092842025253 kg`。后来的 `3.7391 kg` 腰部模型是另一个资产版本；不要用最新版 URDF 悄悄替换成功基线再声称复现。成功发生在装电池和 Jetson 的真机上，并不证明旧 URDF 质量已经准确。
- **别把公开包当现场部署包：** `open_sprite_rl` 的 G74 `model5999` 是保留的 Isaac 候选；G60 `model3450` 是早期跨仿真基线；G59 `model2999` 是更早的原生 50 Hz 回退。本仓库现以 [G74 model3000](../baselines/sprite0825_stage2_g74_model3000/README.md) 为默认，真机还需要现场校准、对应的 native 参数包和运行库。克隆公开仓库不等于具备上电条件。

## 1. 最后稳定行走的训练配方

### 两阶段的区别

1. **Stage 1：给定参考动作的 WBT。** 参考关节状态与相对姿态作为指令，策略在物理环境中跟踪整段动作。它解决的是“能不能以合理接触和负载做出这种动作”。V38 是 Sprite0615 的关键 sim2sim 基线，验证过多速度、多相位、扰动和长循环。参考播放、带参考的 WBT 策略、无参考的手柄行走策略是三件事。
2. **Stage 2：速度控制 + AMP。** G74 actor 只接收自身观测和 `[vx, vy, wz]`，PPO 通过任务奖励学站立、跟速、转向、接触和效率；AMP 判别器用专家片段约束动作分布，不负责给定速度或指定某一帧要踩在哪里。G74 是从零训练的 `UnconditionedAMPPPO`，继承 G72/G73 的训练配方和 G71 专家数据，**不是加载 V38 actor 做蒸馏，也不是训练世界模型**。这借鉴了公开 PM01 的任务/风格分工，不等于复刻厂商完整商业训练流水线。

## 2. GMR / 重定向：踩坑和走出来的路径

### 早期为什么兜圈

- **输入不是真走路，调 IK 也救不回来。** 有两组最早的候选是夸张表演动作，不能把大步、重心奇怪一概归咎于 IK config。先选稳定平地自然走路源片段，再检查目标形态。早期 GMR `walk_6m` 多关节频繁到限位；用户认可的 `bmlrub112_walk1/2` 更自然，但双踝 pitch 仍接近上界。视觉好只是第一关。
- **脚链和地面要独立检查。** 脚看着平、膝盖像走路，不代表足底不穿地、不滑。要用目标机器人 FK 和真实足底碰撞几何检查；仅看踝关节原点或抬高整段根高度会误导。用户认可过早期足底偏移修正的方向，但不要把当时口头的“45”当通用高度参数。新派生模型还要检查碰撞掩码是否真正启用；另一个实验出现过约 4.6 cm 穿地被门槛拦截，不应靠抬轨迹或放松门槛放行。
- **参考初始姿态对齐不等于相位对齐。** 两段 GMR 步态不能共用一个起始帧。早期 30 帧只对齐了初始姿态；walk1/2 更合适的相位窗口分别约 16/79。错误相位会让单膝动作锚点放大左右抢步偏差。给定轨迹回放能明显屈膝，证明不能简单归因于机械不允许；弱附加奖励不改变既有步态，强动作锚点/学习率又可能毁掉接触。
- **空间缩放不能解决关节速度。** 早期 Sprite0615 WBT 的 `timescale150` 指动作总时长拉为 1.5 倍，时间速度约为原来的 2/3，不是增益乘 1.5。用户比较后采用 1.5 而不是 1.75。这是针对当时动作和电机包络的修正，不是 G71/G74 需要再次套用的系数。
- **别把每隔几秒的跳变都叫推搡。** 分开记录外力事件、episode reset、参考循环接缝和初始化。长时无重置闭环、固定起始状态和带时间戳的事件能区分“自己纠正”和“重置回好姿态”。短段不摔倒不代表整段稳定。

### 最终用的不是原始 GMR 输出

最终 G74 的行走专家来自 **PM01 G55 稳态步行 → 源 MuJoCo FK → 语义关键点 → Sprite0825 Mink IK → 接触清理 → G71 V20 → AMP 数据**。这是早期 GMR 实验之后的可审计替代流程，不要把两套数据混成一条生产链。

1. 用足底、髋、上身、肩肘等可对应的几何关系建目标，按关节名处理轴向、默认姿态、尺度和缺失自由度。不同机器人形态不能逐项复制关节角。G71 用髋侧点适应倾斜髋轴，上身目标投到 Sprite 的刚性几何，手臂不强行追一个本机没有的 PM01 肘 yaw 端点。
2. 用 heel/toe 高度与平面速度找接触区间；V20 采用 `0.025 m`、`0.08 m/s` 的检测阈值。用支撑区间锚点平滑修正根 **XY**，保留关节角与根姿态。单独裁掉恰好 1 个未收敛起始帧，所有姿态/关键点/接触数据一起裁剪。任何重采样、清理或速度改变后，重新求一致的速度和 FK，不留下旧导数。
3. V20 留下 1199 帧/100 Hz/11.99 秒，平均约 `0.196 m/s`、148 步/分钟、触地左右交替 100%。最小 heel/toe 高度 `3.69 mm`，接触点平面速度 P90 最大 `9.01 mm/s`，无关节越限。独立复算 NPZ 的 32 个 body FK，位置最大差约 `2.41e-7 m`。这些是**参考运动学**证据，不代表带质量的闭环仿真已通过动力学验收。
4. 用模型真实坐标系做播放和跨格式审计：名称、关节轴、角度单位、quaternion 顺序、body 顺序、默认姿态、足底、根速度坐标、接缝、左右交替。视觉和数值均通过才送训练。早期 V38 的短周期平铺适合 WBT 验证，不适合作为覆盖启停的 AMP 数据；完整 PM01 片段又混有侧向和转弯，若任务只训练直行，要先筛覆盖而不是加一串对抗性奖励。

**可复用的检查顺序：** 源动作正确 → 形态/轴向/FK 对齐 → 足底和限位 → 接触与接缝 → 专家与指令分布匹配 → 物理闭环。不要反过来用 reward 补偿一个未经审核的参考。

## 3. 真正推进项目的几个决定

### 训练与跨仿真

- **从手搓局部步态形状，转到有参考约束的全身运动，再让速度任务学命令响应。** WBT 给出了更可控的相位、接触与动作质量对照，AMP 提供动作分布，不要求手柄 policy 按固定时钟重播单段走路。早期只加膝盖、步长奖励虽然能改指标，却经常换来偏航和接触退化。
- **分开额定、峰值、速度和编码上限。** J4340P 的 `14/40 Nm` 和约 `3.77 rad/s` 额定转速，不等于一条刚性限速线；在约 38 V 的项目环境里，仿真采用过 `9.3 rad/s` 运行上限。踝 J4310P 是另一类电机。训练/评估既看峰值、速度包络，也看持续 RMS。铭牌折线是工程边界，不是厂家实测动态扭矩曲线，更不是允许长期输出峰值的证明。
- **按 50 Hz 重训，而不是把 100 Hz actor 慢放。** G58F 原生 100 Hz，G59 开始原生 50 Hz，历史长度随周期调整。G59 解决了高频小碎步，却出现大步和上身摆动。G60 对一阶/二阶动作差分惩罚按 `dt²/dt⁴` 的效应重新标定，软约束腰 roll 而非锁死。G60 同时有续训后课程计数器归零的混杂，不能把所有改善归于单一权重。复现时应同时固定课程的物理时长和恢复语义。
- **区分中心偏置和扭矩不够。** 四个近端肩关节升级 J4340P 后，G73 仍有双肩 roll 约 `0.105 rad` 常偏差。继承的默认中心 `+0.25/-0.25 rad` 与专家均值冲突。G74 对齐默认姿态、动作偏置和姿态奖励中心至约 `+0.082816/-0.076322 rad`，绝对角 AMP 专家不改，并从零训练。避免用更大扭矩解决错误的坐标原点。
- **Isaac 好不等于 MuJoCo 好，更不等于真机好。** 4090 让并行采样和足量训练可行，但不能仅靠 GPU 型号解释进步。候选比较用实际采样量、物理 `dt`、相同指令、种子和门槛；看站立漂移、正负转向、连续启停、触地、双侧摆腿、足底滑移和电机负载。G74 的 `5999 → 3000` 选择就是跨仿真淘汰的结果。234 的图形回放慢于实时，按仿真时间读指标，不用墙钟直接推断步频。

### 执行器与实机安全

- **策略在串联关节空间，机器人的并联机构在 runtime 处理。** 左右踝分别实测，不复制镜像另一侧；头部 pitch/roll 也分别校准一个 2×2，yaw 独立。线性近似 `q_m = A q_j + b`，反馈解 `q_j = A⁻¹(q_m-b)`，速度不加零点，扭矩用 `τ_m = A⁻ᵀτ_j`，保证虚功一致。踝 500 Hz 用新鲜关节反馈算 PD，送 MIT `Kp=Kd=0` 和前馈力矩；不用先求足端力再绕回来。头部保留 50 Hz 目标映射、内 PD 和交叉前馈，不等同于踝力控。当前矩阵只在已标定工作区可信，非平行四边形带来的非线性不能靠无限放宽 RMS 门槛掩盖。
- **编码器、模型和电机符号不能混。** `encoder_sign` 保持原安装读数约定，直连关节的 5 处反向用 `policy_to_motor_sign`：腰 yaw、左腕 pitch/roll、右腕 roll、头 yaw。命令和反馈双向同约定，软件限位变换也一起验证；并联 pitch 修正放到矩阵列，不翻单只电机。标定 CSV 的小拟合截距与驱动重新写零是两回事。头部 CSV 曾有单行 motor B 符号写反，修正后 RMS 从约 `0.034` 降到约 `0.0011 rad`，先查残差最大的记录再改模型。
- **协议刻度、机械能力、实际控制帽是三份参数。** 读回 MIT PMAX/VMAX/TMAX，例：4340 的 TMAX `28 Nm` 与机械 `14/40 Nm` 不矛盾；4310 为 `10 Nm` 与机械 `3.5/12.5 Nm`。不要为了“和手册一致”只改软件解码、也不要把协议最大值当安全指令。校验 `Kp·误差 + Kd·速度误差 + τff` 的总请求、量化后结果和反馈异常；温度低通及 RMS 用于持续负载检查。命令投影、实测到机械限位和力矩饱和应分开计数。
- **安全验证先低风险后闭环。** 先零增益查询，分总线查 31 个方向、回包、故障；不是假设禁能电机主动广播。再测单电机保持、卸载并联机构、吊装整机、逐渐接地与抗扰，最后站立→慢走→停步。用测得姿态启动和有界增益 ramp，避免上电直接跳到 home；启动姿态的建议门槛不替代硬边界、IMU 新鲜度、超时和独立断电。不要自动写零点。电源也属实验条件：5 A 限流稳压电源上的跌压/驱动故障不能归咎于策略，最终行走记录是电池供电。
- **不要把调试低扭矩参数永久当步行参数。** 早期小扭矩能确认方向与时序，无法承重就不能说明策略不会走。实机从膝和髋的 `130/5`、髋 roll `150/5` 到腰 roll `60/3` 等组别参数逐步对照；后续肩、腕调整避免僵直或高速抖动。`Kd=5` 在这套现场髋/膝对照中可用，不是所有达妙电机通用值。完整最终组别和限扭以封存参数及 [ICM 真机记录](https://github.com/BeijingDynamics/open_sprite_runtime/blob/250da14/docs/ICM45686_WALKING_20261016.md) 为准，不能再叠旧增益倍率，也不能拿仿真合同直接发电机。

### IMU、时序和 native 化

- **先保住观测语义，再缩短时延。** Actor 用的是机体系角速度与投影重力，不直接吃四元数或加速度。原始 gyro 扣 15 秒静止零偏，再过安装旋转；融合的修正量不混入 gyro 观测。加速度用于软件重力估计，动态加速度不是重力，估计积分用实际样本 `dt`。六轴没有磁航向，开机归零不等于长期航向不漂；纯 yaw 误差也不直接改变投影重力。把 raw specific force 换进已有 795 维模型是错误，若要换必须另训并验证。
- **可复现的进步：** Yahboom 输出融合姿态/串口 → BNO055 试验 → BNO 原始六轴软件估计（200 Hz 主机采集）→ ICM45686 原始 SPI 六轴 800 Hz、DRDY 时间戳。BNO 原始路径已经有三次走直改善；换 ICM 后同权重/同增益下再次通过三次行走。支持传感路径改进有效，但不能把收益精确分给 ODR、滤波、接口、偏差或 GC 中的任一项。
- **控制环互不阻塞。** 最终是独立 native IMU 生产者、ONNX Runtime CPU actor、CAN/踝实时控制；最新快照、有界 IPC、单调时间戳、过期拒绝，控制线程不等待推理、手柄或磁盘。频率分别是 CAN 调度 `2 kHz`、每个踝电机 `500 Hz`、其余 27 电机 `50 Hz`、actor `50 Hz`、电机内部 MIT/电流环 `1 kHz`，**不是 31 台电机都按 2 kHz 发包**。50 Hz 关节目标按零阶保持，避免随意插值改变接口。
- **测时延分清数据年龄和传感器延迟。** 120 秒 ICM 零增益 shadow 有 6000 帧、在线离线输出逐字节相同，接受样本约 792.2 Hz，最大间隔约 `2.53 ms`；policy 消费年龄 p99 `6.57 ms`、最大 `7.34 ms`，推理计算最大约 `1.85 ms`。这是 DRDY 到主机使用的测量，未包含无法由它单独测出的内部滤波延迟。尾部延迟比平均速率更重要；不要把所有间隔都归为 I²C 或 Python GC。独立 native 化去掉了 Python GC 对关键路径的耦合，不能保证内核调度永远无长尾。
- **ICM 的 SPI 坑值得记住。** `WHO_AM_I` 读 0 时，16-bit 一次事务内发送 `F2 00`，CS 中途不能拉高；SCK 先在 40-pin 裸口和回环验证，再到模块端测。最终问题是把四个**串联电阻**错当上拉拆掉，芯片和 SPI 实际断路。修板后恢复，不靠更换读寄存器字节序。稳定部署为 mode 3、请求 1 MHz、800 Hz ODR、INT1；请求频率不是示波器读数。SPI runtime PM 的长尾用有界运行包装处理并退出恢复。6400 Hz FIFO 只做独立演示，不是步行基线。

## 4. 后退与 SuperMimic：没有被解决的部分

- G74 的命令分布没有负 `vx`，专家也没有合格倒走。放开手柄负值不是实现后退。不能用偶尔向后漂移、站住不倒或输入/IPC parity 当成倒走验收。更换新模型、IMU 观测、后退参考和 reward 一起做，会让问题无法归因。
- 后退重训有可用的证据，不应整串搬进新工程。保留有代表性的正向回归与倒走失败轨迹。比如 50 Hz 的触地滑移分位数会受抽样相位影响；高频触地事件积分与低频门槛过线是不同证据。没有通过真机后退验收的模型，不替换已经能走的版本。
- 后来的 SuperMimic 分支不是 AMP/PPO 基线。先把机器人模型、串联 PD/限位和已复现的 tracker 配方对齐；不要把并联、MIT 量化、runtime 保护塞进首轮训练来混淆诊断。到了 24,000 轮仍不等于升级：17,175 轮长测的跟速更准却停步更差，末轮零指令会后退转圈，约 21,280 轮起速度 critic loss 上升，根因未完全确定。生存率没有拦住任务失效。保留中期模型和 中期与末轮的复盘证据，不把末轮 ONNX 放到真机。
